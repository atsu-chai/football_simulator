表示の基準再生倍率を2.8から1.7へ変更。1200シミュレーション秒の試合は、1×で約11分46秒（停止時間を除く）。1/2/4×の操作は維持する。

距離は停止中も含む実際の座標移動を集計し、キックオフ等の瞬間的な再配置を除く。「90分換算」は実移動距離に5400/1200を掛けた参考値であり、短縮された1試合で実際に走る距離ではない。`before.json` と `after.json` に選手別の値も保存した。

原因と変更:

- 表示倍率2.8によって、実移動の平均4.30 m/sが画面上12.03 m/s相当になっていた。
- 通常の位置調整にも高い速度が割り当てられ、最大6.5 m/s²で向きを変えていた。通常移動を歩行・ジョグ寄りにし、加速度を通常2.5、追走3.5 m/s²へ変更した。
- 目標は0.15/0.5秒の時定数で追従し、到着前に減速、通常時は0.8 mの範囲で停止する。
- 味方からの押し戻しの範囲を3から1.8 mへ狭め、希望速度を最高速度以下に抑える。
- サポート位置の相対/絶対座標を値の大きさで推測していた。保持者IDで基準を明示し、サポート・空き場所の再探索を1.2〜1.6秒間隔にし、小さな評価差で目標が変わりにくくした。
- 最高速度7.6 m/s、ボールの物理速度、TICK=0.1秒、MATCH_SECONDS=1200を維持。描画のprev→pos補間に問題は見つからなかった。
- 移動を変えた後のシュート増を抑えるため、選択評価のxG係数を6から5.5、加算値を0.2から0.12へ変更した。

実行環境: `npx tsx` はIPC用ソケットがEPERMとなるため、同じTSを `NODE_USE_SYSTEM_CA=0 node --import tsx ...` で実行した。NODE_USE_SYSTEM_CA=0は、この環境のシステム証明書読み込みで起きるSecItemCopyMatchingエラーを避けるためにコマンド単位で指定した。

Viteのローカル待受もEPERMで拒否された。ブラウザーでの動きの目視確認は未実施。ヘッドレスでの計測と、既存の描画処理の確認に限る。
